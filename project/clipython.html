CipherVault : Chiffrement Hybride RSA / AES

Application Python de sécurité implémentant un pipeline de chiffrement hybride pour échanger et sceller des fichiers sensibles sans intermédiaire.

Open-Source Python 3 RSA-2048 (OAEP) AES-256 (GCM Authentifié)
Dépôt GitHub ↗ ← Tous les projets

1. Pourquoi ce projet ? Comprendre la cryptographie en profondeur

Objectif d'Apprentissage

Pendant ma formation en cybersécurité et réseaux, nous avons étudié les principes théoriques de la cryptographie : les clés publiques et privées, les fonctions de hachage et les chiffrements par bloc. Mais voir des formules mathématiques au tableau ne suffit pas pour comprendre comment un logiciel protège réellement des données sur un disque dur.

J'ai codé CipherVault pour manipuler directement les primitives cryptographiques réelles en Python : générer des paires de clés valides, empaqueter des fichiers en binaire, gérer les vecteurs d'initialisation (IV) et vérifier les tags d'intégrité sans utiliser d'outils propriétaires fermés.

2. Pipeline Cryptographique Hybride

Schéma RSA + AES

Le chiffrement hybride résout le dilemme classique : RSA est sécurisé pour l'échange de clés mais trop lent pour de gros fichiers ; AES est ultra-rapide mais nécessite un secret partagé.

Étape 1
Clé de Session AES
Génération d'une clé symétrique éphémère de 256 bits (32 octets) et d'un vecteur d'initialisation aléatoire (IV de 96 bits) via un générateur CSPRNG.
Étape 2
Chiffrement Payload
Le fichier (image, texte, PDF) est chiffré par flux avec AES-256 en mode GCM (Galois/Counter Mode). Le mode produit à la fois le chiffré et un tag d'authentification de 128 bits.
Étape 3
Scellement RSA
La clé éphémère AES de 32 octets est chiffrée avec la clé publique RSA-2048 du destinataire (rembourrage OAEP avec hachage SHA-256).
Étape 4
Conteneur .cvault
Assemblage binaire : Magic Header (CVLT) + Clé AES chiffrée + IV + Tag d'authentification + Données chiffrées.

3. Les Défis Techniques Rencontrés & Comment je les ai résolus

Les pièges courants de la cryptographie appliquée et les choix d'implémentation.

Défi 01 · Limite de taille RSA

Pourquoi ne pas tout chiffrer directement avec RSA ?

Le Problème :

Une clé RSA de 2048 bits ne peut mathématiquement pas chiffrer un message plus grand que son module. Avec le schéma de padding sécurisé OAEP (SHA-256), la charge utile maximale est de seulement 214 octets. Impossible de chiffrer une photo ou un document directement.

Ma Solution :

Architecture hybride standard : RSA ne chiffre QUE la clé de session AES (qui fait 32 octets, largement sous les 214 octets limites). AES chiffre ensuite le fichier réel sans limite de taille et à la vitesse native du processeur.

Défi 02 · Intégrité des données

Garantir que le fichier n'a pas été corrompu ou altéré

Le Problème :

Le mode AES classique (CBC) ne garantit que la confidentialité, pas l'intégrité. Un attaquant peut modifier des octets dans le fichier chiffré sans que le déchiffrement ne génère d'erreur visible (attaques par bit-flipping ou padding oracle).

Ma Solution :

Adoption exclusive d'AES-GCM (chiffrement authentifié avec données associées - AEAD). Si ne serait-ce qu'un seul bit du fichier est modifié en cours de route, le tag d'authentification de 16 octets échoue immédiatement et lève une exception InvalidTag.

Défi 03 · Format Fichier Binaire

Empaqueter toutes les pièces dans un format propre et portable

Le Problème :

Pour déchiffrer, le destinataire a besoin de la clé de session scellée, de l'IV, du tag d'authentification et du flux chiffré. Séparer ces éléments dans plusieurs fichiers était confus pour l'utilisateur.

Ma Solution :

Création d'une structure binaire unique avec le module Python struct : 4 octets d'en-tête d'identification (CVLT), 2 octets pour la taille de la clé RSA, le bloc de clé scellé, 12 octets d'IV, 16 octets de tag et le flux chiffré complet.

Défi 04 · Sécurité des clés

Stockage et export des clés au format standard PEM

Le Problème :

Stocker des clés privées en texte brut sur le disque dur est une faille majeure de sécurité si la machine est compromise ou prêtée.

Ma Solution :

Export standardisé PKCS#8 avec chiffrement de la clé privée par mot de passe utilisateur (dérivation de clé PBKDF2 HMAC-SHA256 avec sel aléatoire) et export public X.509 pour le partage facile entre correspondants.

ciphervault/crypto/hybrid_engine.py Python (cryptography) 
import os, struct
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
from cryptography.hazmat.primitives.asymmetric import padding
from cryptography.hazmat.primitives import hashes

def encrypt_hybrid_container(payload_bytes: bytes, recipient_rsa_public_key) -> bytes:
    # 1. Génération d'une clé éphémère AES-256 et d'un vecteur d'initialisation IV (96 bits)
    aes_session_key = AESGCM.generate_key(bit_length=256)
    iv = os.urandom(12)

    # 2. Chiffrement authentifié du contenu avec AES-GCM (produit ciphertext + tag 16B)
    aesgcm = AESGCM(aes_session_key)
    encrypted_payload = aesgcm.encrypt(iv, payload_bytes, associated_data=None)

    # 3. Scellement asymétrique de la clé AES avec la clé publique RSA (Padding OAEP sécurisé)
    encrypted_session_key = recipient_rsa_public_key.encrypt(
        aes_session_key,
        padding.OAEP(
            mgf=padding.MGF1(algorithm=hashes.SHA256()),
            algorithm=hashes.SHA256(),
            label=None
        )
    )

    # 4. Construction du conteneur binaire CVLT : [MAGIC 4B][KEY_LEN 2B][ENC_KEY][IV 12B][PAYLOAD]
    magic_header = b"CVLT"
    key_length = len(encrypted_session_key)
    header_pack = struct.pack(">4sH", magic_header, key_length)

    return header_pack + encrypted_session_key + iv + encrypted_payload

Ce que ce projet m'a appris en autodidacte

  • • Ne jamais réinventer les algorithmes de chiffrement : Utiliser des bibliothèques cryptographiques reconnues et testées (comme cryptography en Python) plutôt que d'essayer d'implémenter soi-même les calculs mathématiques dans son coin.
  • • L'importance du chiffrement authentifié (AEAD) : La confidentialité seule ne sert à rien si on ne peut pas prouver que le message n'a pas été modifié. GCM est indispensable.
  • • La manipulation des flux binaires : Gérer des formats de paquets octet par octet avec des en-têtes et des tailles dynamiques donne une vision beaucoup plus claire de ce qui voyage sur le réseau ou est écrit sur le disque.
